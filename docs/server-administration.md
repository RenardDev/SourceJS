# Bundled server administration

The `server-administration` plugin is installed in `addons/sourcejs/plugins/server-administration` and loads automatically. The commands are available to the server console without a player permission. In-game administrators use the existing SourceJS authorization configuration. Ordinary players do not gain moderation rights by installing the package.

## Add an administrator

For selected permissions, use the server console or an authorized RCON session.
Use the exact network ID reported by the game, including its Steam2 universe
prefix. For example:

```text
sjs auth permission player add "STEAM_1:0:12345" sourcejs.kick
sjs auth permission player test "STEAM_1:0:12345" sourcejs.kick
```

Use `sjs auth` for help. To revoke a direct grant, use `remove` instead of
`add`. These commands are unavailable in an ordinary player console. An
authenticated engine RCON session can run them with `rcon sjs auth ...`.
Changes are saved in `cfg/sourcejs/auth/players.json`
and apply without restarting. A permission can still be inherited from a group
or granted by `simple.txt` after the direct grant is removed.

For trusted operators who should have **all** SourceJS permissions, add one
network ID per line to `cfg/sourcejs/auth/simple.txt`. Do not add quotes or
flags. Blank lines are ignored and `#` starts a comment:

```text
STEAM_1:0:12345 # server owner
```

SourceJS reads this file when checking permissions. Remove the line to revoke
the blanket grant; individual grants and group memberships are unaffected.
The `sjs auth` commands do not edit `simple.txt`.

Use `sjs_kick "Player Name" reason` in a console, `!kick "Player Name" reason` in public chat, or `/kick "Player Name" reason` to hide the invocation. `!` leaves the original message in the same public or team chat channel. `/` suppresses only recognized commands, even if access is denied; unknown text passes through unchanged. Single-line replies to chat commands go privately to the invoking player's chat when supported. Console commands and longer replies use the player's console. Use `/`, not `!`, for sensitive arguments or private messages.

If a game client does not forward a bare command such as `sjs_help`, try
`cmd sjs_help` in the client console, or `/help` in chat. Help does not require
any permission. SourceJS can intercept stock chat commands even when the
engine bypasses the ordinary plugin client-command callback. This depends on
the [SDK console interface and registered chat commands](api/commands-say.md),
not the game name.
Use `sjs plugins list` in the server console to verify that
`server-administration` is loaded. Server console commands, including commands
run through RCON, have no player identity; use a name or `#userid` instead of
`@me` from those consoles.

## Languages

The bundled administration and protection plugins include original translations for the 31 languages listed under
[Full Platform Supported Languages in Steamworks](https://partner.steamgames.com/doc/store/localization/languages).
This covers administration menus and submenus, built-in ban reasons, vote controls and results, map announcements,
moderation replies, validation errors, player preferences, effect countdowns, flood warnings, and reserved-slot messages.
Each recipient sees localized announcement labels. Command names, permissions, map and player names, and message text
entered by players or administrators are unchanged.

For chat, menus and HUD, each recipient uses the game client's reported language. When that language or a phrase is
unavailable, SourceJS tries the server language (`DEFAULT_LANGUAGE` in `addons/sourcejs/data/languages.ini`) and then
English. Server and client consoles always receive the built-in English text, including when a chat reply falls back to
the console. Technical logs are not translated. The Steamworks **Game Support Only** list does not supply client API codes.

Catalogs live under `resource/sourcejs/translations/server-administration/` and
`resource/sourcejs/translations/server-protection/`, with one UTF-8 JSON file per language. To customize a phrase without
editing files shipped by SourceJS, create a sibling override such as `ru.server.json` in the appropriate directory.
Use the same phrase key and keep every named placeholder, such as `{Map}` or `{Seconds}`. Bad overrides fall back to
the packaged phrase. Reload the plugin or change the map to pick up edits.

## Commands and permissions

| Permission | Commands (add `sjs_` in the console) |
| --- | --- |
| `sourcejs.admin` | `admin`, `who`, `play` |
| `sourcejs.ban` | `ban`, `abortban`, `banip` (arbitrary IPv4 also requires `sourcejs.rcon`) |
| `sourcejs.unban` | `unban` |
| `sourcejs.kick` | `kick` |
| `sourcejs.slay` | `slap`, `slay`, `rename`, `burn`, `beacon`, `blind`, `freeze`, `noclip`, `gravity`, `timebomb`, `firebomb`, `freezebomb`, `drug` |
| `sourcejs.cheats` | Additionally required for `noclip` (console and menu). |
| `sourcejs.chat` | `gag`, `ungag`, `mute`, `unmute`, `silence`, `unsilence`, `say`, `chat`, `csay`, `dsay`, `hsay`, `msay`, `tsay`, `psay` |
| `sourcejs.cvar` | `cvar`, `resetcvar` (protected variables also need `sourcejs.password`; cheat variables need `sourcejs.cheats`) |
| `sourcejs.config` | `execcfg`, `reloadadmins` |
| `sourcejs.rcon` | `rcon`, `addban` |
| `sourcejs.map` | `map`, `setnextmap`, `maphistory`, `nominate_addmap`, `mapchooser_refresh` |
| `sourcejs.vote` | `vote`, `cancelvote`, `votemap`, `votekick`, `voteban`, `voteslay`, `voteburn`, `votealltalk`, `voteff`, `votegravity`, `mapvote` |
| No permission required | `help`, `searchcmd`, `votefor`, `revote`, `currentmap`, `nextmap`, `timeleft`, `thetime`, `ff`, `motd`, `listmaps`, `nominate`, `rtv`, `settings`, `cookies` |
| Server console only, when SQL administration is enabled | `create_adm_tables`, `update_adm_tables`, `sql_reload`, `sql_addadmin`, `sql_deladmin`, `sql_addgroup`, `sql_delgroup`, `sql_setadmingroups` |

Use `sjs_help [page|search]` for syntax. Grant `sourcejs.rcon`, `sourcejs.config`, and protected ConVar permissions only to trusted operators: they can change server behavior beyond player moderation. `sjs_rcon <command> [arguments]` accepts one engine console command. Its output stays in the server console; an in-game caller only gets a submission status. `sjs_execcfg <filename.cfg>` accepts a basename made of letters, digits, underscores or hyphens followed by `.cfg`. The file must exist in the game's `cfg` search path. A successful reply confirms submission to the engine, not that every command in the file succeeded.

- Target a connected player by unique name, unique partial name, `#userid`, or exact `#name` / `#Steam2 ID`. Group-capable commands also accept `@all`, `@bots`, `@humans`, `@alive`, `@dead`, `@me` and `@!me`. A player with `sourcejs.immunity` cannot be targeted by a different player without `sourcejs.targetimmune`. The server console can always target a player.
- Use `0` minutes for a permanent ban. Only permanent bans request a ban-list write; unban requests a rewrite of the list. Offline `sjs_addban <minutes|0> <Steam2 ID|Steam3 ID> [reason]` and `sjs_unban <Steam2 ID|Steam3 ID|IPv4>` accept individual Steam IDs; IP bans use IPv4. `addban` checks offline immunity in native and enabled SQL authorization unless the caller has `sourcejs.targetimmune`. The optional offline reason is validated but not stored in the engine list. Steam ID bans are unavailable in LAN mode; use `sjs_banip` there. Command responses confirm requests, not engine acceptance or successful persistence. A failed write request or unconfirmed kick is reported separately.
- `sjs_banip` reads the current IPv4 address when given a player target and refuses to use a stale connection. An explicit address requires `sourcejs.rcon` in addition to `sourcejs.ban`. Both `0` and `0.0.0.0` are rejected as addresses. When a player ban is submitted through `sjs_ban`, its menu, or a successful ban vote against a connected player, `sjs_show_activity` controls the notice. The notice includes the target name and duration, but no ban reason, IP address, or Steam ID.
- `sjs_help [page|search]` lists up to ten numbered commands per page. A nonnumeric argument filters the command names and usage. `sjs_searchcmd [command fragment]` searches bundled command names without regard to case or pagination. Both write to the caller's console and use the same access checks as dispatch. In-game lists omit server-only commands and commands the player lacks permission to run; the dedicated console omits player-only commands such as `revote` and `settings`. `sjs_cookies` remains listed because the console can read the cookie catalog, but not an individual player's preferences. When invoked from chat, both commands point the caller to their console. The lists do not include commands registered by other plugins.
- `sjs_cvar <cvar> [value]` reads or sets a ConVar; `sjs_resetcvar <cvar>` restores its engine default. Protected values are never printed by these commands. Do not enter secrets in chat or in a shared console. The server console can run `sjs_cvar protect <cvar>` to make that ConVar console-only for the current plugin load; `sjs_show_activity` is console-only by default. To set or reset `servercfgfile` or `lservercfgfile`, a player also needs `sourcejs.config`. Setting either accepts only a `.cfg` basename or an empty string.
- With `sourcejs.admin`, use `sjs_who` for a console list of connected players and the permissions they hold that bundled commands declare. `sjs_who <target>` reports one player; the admin menu offers the same lookup under `admin → Identify player`. The report includes direct and inherited grants from the current authorization state, including enabled SQL authorization when its cache is available. A listed permission does not mean that every command that uses it is available; for example, `noclip` still needs both `slay` and `cheats`. The report does not list unrelated permissions or authorization account names. A targeted lookup respects immunity, including changes after the menu opens. Chat and menu results go only to the caller.
- `sjs_kick <target> [reason]` requires `sourcejs.kick`. Use `/kick` or `!kick` without arguments to open the player picker; the console displays usage instead. The picker uses the default reason and rechecks permission, identity and immunity when selected. Direct commands accept group selectors. If the caller is in the group, SourceJS processes that player last. A group containing an immune player is rejected unless the caller can target immune players. The result counts requests accepted by the engine, not confirmed disconnects. After acceptance, `sjs_show_activity` controls whether other players see the action and whether they see the administrator's name. The kick reason is not included in the activity message or server log. The log records caller and target UserIDs.
- The admin menu offers player selection for kick, ban, slay, gag, mute and Fun Commands. A menu ban requires a connected human target, a duration and a reason. Choose a preset or select the custom reason and type it in chat; that message is consumed instead of broadcast. Use `/abortban` or `sjs_abortban` to cancel the pending reason. Disconnect, map change and plugin unload also clear it. Presets can be replaced with a JSON array of single-line strings in `cfg/sourcejs/server-administration/BanReasons.json`. Direct `sjs_ban <target> <minutes|0> [reason]` is unchanged.
- Gags block `say`, `say_team`, and incoming `say_squad` on games that support it; mutes suppress voice. Both are session-scoped and cleared on disconnect or plugin unload. Beacon, sound, burn and HUD/menu delivery require the corresponding game support. For `blind` and `gravity`, select a player and then a preset. The menu hides `blind` if the game does not support `Fade`. Access and target immunity are checked again when the action is selected.
- `sjs_dsay <message>` sends a green HUD announcement for three seconds when the game exposes `HudMsg`. `sjs_hsay <message>` requires `HintText` and does not fall back to ordinary chat. `sjs_tsay [color] <message>` sends a top-left notification, white by default; for example, `sjs_tsay lightblue "Round starts soon"`. `sjs_psay <target> <message>` shows the sender and recipient names and sends only to the specified human player and the sender (once for a self-message).
- `sjs_msay <message>` opens a dismissible ten-second panel for connected human players. Like private chat, its header shows the actual sender regardless of `sjs_show_activity`. Use a literal `\n` in a console argument to start a new line. An unavailable panel for one player does not close the panels that other players received.
- With `sourcejs.chat`, use `@ message` in all-chat for an announcement, `@@ "player name" message` for a private message, or `@@@ message` for a centered announcement. In team chat and in squad chat on games that provide it, `@ message` goes only to the sender and players with `sourcejs.chat`. Set `sjs_chat_mode 0` to disable this shortcut for non-admins (default: `1`). Denied private messages and requests to staff are not forwarded to ordinary chat. A gag still blocks these shortcuts.
- `sjs_show_activity` controls attribution for `say`, `csay`, `dsay`, `hsay`, `tsay` (including their public chat shortcuts). Add flags `1+2` to show names to ordinary players and `4+8` to show names to recipients with `sourcejs.admin` or `sourcejs.chat`. Flag `16` always reveals names to recipients with `sourcejs.activity.seenames`. The default `13` shows names to administrators and displays `Admin` to other players. Explicit announcements remain visible when the name is hidden. For automatic `ban`, `kick`, `play`, `cvar` and `resetcvar` activity, an audience without its visibility flag (`1` or `4`) receives nothing unless flag `16` applies. ConVar notices omit the value and are not sent for protected or console-only variables, failed writes, or unchanged values. The caller receives the usual command reply. Announcements from the console use the recipient's translation of `Console`. Private messages and administrator-only chat are unchanged.
- `freeze <target> [seconds]` without a duration toggles the plugin's freeze using `sjs_freeze_duration` (default: 10 seconds), also used by `freezebomb`. An explicit positive duration sets or renews a freeze; `0` only clears it. The plugin checks that movement was actually disabled before applying the tint or announcing a freeze. A failed thaw leaves the freeze record intact so the command or timer can retry. A frozen player gets a private countdown and thaw notice; the blue tint, glow, and positional freeze/thaw sound depend on game support. On expiry, round end, map end, or unload, the plugin attempts to restore the previous movement mode and color where it still owns them. `freeze`, `noclip` and `gravity` require the matching writable SDK datamap fields. `blind <target> [opacity]` submits a persistent black fade to each eligible live human client. Opacity is clamped to 0–255; omit it or use `0` to send a clear. A group command reports the number of accepted sends; one rejection does not stop sends to other eligible players. The command does not track the fade for automatic cleanup by the plugin.
- `sjs_beacon <target> [0|1]` shows two expanding rings just above the live target's feet and plays a positional blip at eye level every second. Omit the mode to toggle, pass `0` to cancel, or pass `1` to enable without restarting an existing beacon. Actual starts and cancellations follow `sjs_show_activity`; rejected and unchanged requests are not announced. The inner ring follows team changes and uses the GameData fallback color for unknown teams. Set `sjs_beacon_radius` to change the radius (default: 375). A beacon stops on death or disconnect and is not transferred to a replacement client.
- `sjs_gravity <target> [multiplier]` accepts finite decimal multipliers in the engine's float range. Negative values are clamped to zero; omit the multiplier to restore `1`. The command counts a change only after reading back the new value on the same connection; a repeated value does not trigger a write or an activity notice. A failed write to one group member does not prevent changes to the others.
- `sjs_noclip <target>` requires both `sourcejs.slay` and `sourcejs.cheats`. It toggles noclip and walk for live targets and leaves plugin-owned freezes intact. Group requests report confirmed changes; a failed write to one target does not prevent changes to the others.
- The gravity and blind menus check the target again before opening presets and before applying a choice. If the target disconnects, dies, or becomes immune, the action is rejected and the picker shows the current eligible players. If none remain, use **Back to actions** to leave the picker.
- Successful `blind`, `burn`, `freeze`, `gravity`, `noclip`, and `drug` actions announce the result to other eligible players according to `sjs_show_activity`. The caller still gets the command reply. Rejected actions, unsupported effects, and idempotent `drug` requests do not produce an activity notice. A successful `voteburn` reports the vote result without a separate administrator burn notice.
- `sjs_timebomb <target> [0|1]` shows the countdown in the center of players' screens, tints the target, and pulses rings and positional sound until the explosion. Set `sjs_timebomb_ticks` to change the fuse (default: 10 seconds) and `sjs_timebomb_radius` to change the blast radius (default: 600). The default `sjs_timebomb_mode 0` affects only the target. Modes `1` and `2` also damage nearby teammates or all nearby players, respectively. Omit the second argument to toggle, pass `0` to cancel, or pass `1` to enable without restarting an existing fuse. The argument is not a duration: use `sjs_timebomb_ticks`, `sjs_firebomb_ticks`, or `sjs_freezebomb_ticks` to change the relevant fuse. Actual starts and cancellations are announced according to `sjs_show_activity`; rejected and unchanged requests are not announced. Assets come from `funcommands.games.txt`; a missing asset can be replaced by an available stock sample or sprite, and the game may omit a visual or sound it does not support.
- `sjs_firebomb <target> [0|1]` and `sjs_freezebomb <target> [0|1]` use the same visible countdown and toggle semantics as `sjs_timebomb`. Each has its own `sjs_<command>_ticks`, `sjs_<command>_radius`, and `sjs_<command>_mode` with the same defaults and mode numbers. The firebomb shows stacked orange blast rings and ignites its target for `sjs_burn_duration` seconds (default: 20); secondary targets burn for less time as distance increases. The blast uses the top ring's center when its sprites are available, or the target's eye position when they are missing, regardless of whether anyone can see the rings. The freezebomb draws beams to affected secondary targets where supported and applies a freeze for `sjs_freeze_duration` seconds (default: 10), or thaws players already frozen by the plugin. It does not clear a freeze imposed by the game or another plugin.
- A blast skips an individual nearby player if their position cannot be read or if the slot no longer belongs to the same player. Other eligible targets still receive the blast. A failed timebomb slay does not stop its area damage.
- If bombs and freezes overlap, the most recently applied effect owns the visible tint. Removing it reveals any remaining effect. When all effects stop, SourceJS restores the original color only if no other code changed it in the meantime. Disconnect cleanup stops timers without writing back to the old player slot.
- `sjs_drug <target> [0|1]` sends a random colored fade every second to the affected live human player. Where the SDK and GameData support `EyeAngles` and `Teleport`, it also applies a random view roll between `-25` and `25` degrees and resets the roll on cleanup. Unsupported view roll leaves the fade active. Omit the mode to toggle the effect, or pass `1` to enable it and `0` to stop and clear it. Pending beacons, bombs, freezes and drug pulses are cancelled as soon as the engine reports `player_death` for the target; their timers also check for death. Round end, disconnect, map end and plugin unload clean up remaining effects. If the game does not expose a supported round-end event, map-end cleanup still runs.
- `slay` and `burn` use the matching [stock SDKTools GameData](api/players-entity.md#commands-events-and-moderation). On unsupported platforms or without verifiable data they report failure rather than sending a client command or guessing a native entry. `sjs_burn <target> [seconds]` uses `sjs_burn_duration` (default: 20 seconds), also used by `firebomb`. Explicit durations may be fractional and must be greater than zero and at most 300 seconds. The command ignites the player without forcing health loss. In a dedicated L4D2 test, the command attached a flame to a survivor bot without reducing its health. The same bot could take burn damage from other sources.
- Command votes display one in-game menu for up to 20 seconds. A vote ends earlier when everyone has voted, exited the menu, or disconnected. Disconnecting withdraws that player's ballot. Press the number next to the choice in the radio menu, or click the choice in the dialog on games without the radio user message. An accepted menu ballot requests a local click for the voter only. `/votefor <number>` does not echo the command. While the vote is open, an eligible player can use `/revote` or `sjs_revote` to reopen it for the time remaining. A successful reopen withdraws the previous ballot, so select again to have a vote counted.
- If another SourceJS menu replaces a ballot, the vote stops waiting for that menu on the next tick. The replacement stays open. The player remains eligible to use `/revote` or `/votefor` until voting ends.
- Vote progress is private by default. Set `sjs_vote_progress_chat`, `sjs_vote_progress_console`, or `sjs_vote_progress_client_console` to `1` to announce who voted and what they chose in chat, the server console, or client consoles, respectively. `sjs_vote_progress_hintbox 1` shows an aggregate count, time remaining, and up to three leaders while a ballot is open. It uses the game's `HintText` message and does not fall back to chat. All four settings default to `0`.
- `sjs_admin` groups tasks by purpose and labels actions by what they do, such as **Kick a player** or **Toggle player beacon**. Voting menus explain how to cast a ballot and offer **Skip vote**; short ballots do not show paging controls.
- `sjs_menu_sounds 0` disables feedback in bundled vote, administration, map, nomination, announcement and settings menus. The default is `1`. GameData `core.games/common.games.txt` can configure the choice and close sounds; an empty entry leaves the corresponding action silent. If a configured sample is unavailable, SourceJS checks `addons/sourcejs/gamedata/MenuSounds.json` for audio provided by that game's client. The L4D2 profile uses its own accept, focus and back sounds for selection, paging and closing. These files need not be installed on the dedicated server and do not require a download. Without an available client sample, SourceJS tries installed stock sounds and then the bundled `sound/sourcejs/menu-select.wav`, which requires the server's usual download setup. The cue is non-positional and only the player who acted receives it. Opening, redrawing or programmatically closing a menu is silent.
- Action votes also require the relevant `map`, `kick`, `ban`, `slay` or `cvar` permission. Yes/no action votes require Yes to win and reach the configured fraction of votes cast. The defaults are `0.60` for `sjs_vote_alltalk`, `sjs_vote_ban`, `sjs_vote_burn`, `sjs_vote_ff`, `sjs_vote_gravity`, `sjs_vote_kick`, `sjs_vote_map`, and `sjs_vote_slay`. Abstentions do not count. No action is taken on an empty ballot, after the map ends, or if the initiator leaves or loses permission. `sjs_voteban_time` sets the ban duration in minutes (default: 30; `0` is permanent).
- `sjs_vote` and `sjs_votemap` read up to five choices or map arguments, respectively. A generic vote or a vote among several maps picks a random winner from the tied leaders; a tied yes/no action vote does not pass. A successful `sjs_votemap` schedules the map change for five seconds later. Direct `sjs_map` still waits three seconds. SourceJS cancels the pending change when the map ends and rechecks the initiator's permission and the map's availability before executing it.
- A player who disconnects before voting ends loses their ballot. The final tally also checks that each ballot still belongs to the original engine user ID, so a replacement player cannot inherit the ballot or vote through the previous player's menu.
- If a vote menu cannot be sent to a player, that player does not enter the voting pool. Other players can still vote. Menu closure and sound errors do not discard a valid ballot or interrupt the tally.
- If a ban vote passes after the target disconnects, SourceJS bans the Steam ID captured when the vote started, not the player now in that slot. If no valid Steam ID was available, no offline ban is issued. Offline vote bans still check account immunity and are unavailable in LAN mode.
- `sjs_votealltalk` uses `sv_alltalk` when available. Otherwise it requires both `sv_talk_enemy_living` and `sv_talk_enemy_dead`: a passed vote disables both if both were enabled when it started, or enables both otherwise. If the engine refuses a write, SourceJS attempts to restore the values from immediately before applying the vote. No game-name check is used.
- `sjs_votegravity` requires `sourcejs.vote` and `sourcejs.cvar`, and reads the first five arguments as integer gravity values from `0` through `10000`. A single distinct value starts a yes/no vote using `sjs_vote_gravity`; a vote among multiple values chooses the leader or breaks a tie randomly among the leaders. A successful ballot changes `sv_gravity`; a rejected write is not reported as applied.
- `sjs_voteburn <target>` and `sjs_voteslay <target>` require `sourcejs.vote` and `sourcejs.slay` and accept one live target. The passed vote only applies to the same connected player if still alive, and target immunity is checked again. `sjs_voteburn` ignites the target for 19.8 seconds; `sjs_burn_duration` only controls the default for `sjs_burn` and `sjs_firebomb`.
- `sjs_vote_delay` sets the minimum time after an administrative vote finishes or is cancelled before another can start (default: 30 seconds; `0` disables it). The server console and players with `sourcejs.cvar` or `sourcejs.vote_delay_bypass` bypass the delay, but cannot start a vote while one is active. Map rotation and Rock the Vote do not use this command cooldown.
- `sjs_map <map>` announces a three-second delay. In chat, `!map` or `/map` without an argument opens the map-cycle picker for players with `sourcejs.map`, even without access to the full admin menu. The console command still requires a map name. A new request replaces any pending one. The pending change is cancelled on map end or plugin unload, or if its initiating player leaves or loses map permission.
- `sjs_setnextmap <map>` requires `sourcejs.map` for player callers and accepts any installed map, even if it is outside the cycle. It updates `nextlevel`, announces the choice according to the activity policy, and does not end the current map. After a successful write, automatic MapChooser checks stop and an already-open rotation ballot cannot replace the choice. An invalid map or refused write leaves the previous choice and vote scheduling unchanged.
- In the administration menu, choose `map` or `setnextmap` under map actions to pick from the current map cycle. Under voting actions, `votemap` lets you select up to five distinct maps, review the list, and confirm the ballot. `votekick` opens a player picker; `voteban` lists only humans and uses `sjs_voteban_time`. Both menu actions use the default reason; supply an optional reason when using the command. `voteburn` and `voteslay` open a live-player picker; `votegravity` starts a ballot with `200`, `400`, `800`, `1600`, and `3200`; `votealltalk` and `voteff` start yes/no ballots. `cancelvote` stops the current vote. SourceJS rechecks permissions on selection and checks that selected maps or players are still available.
- With `sourcejs.config`, choose `config` in the administration menu for `execcfg` and `reloadadmins`. The config picker lists only installed files named in `cfg/sourcejs/server-administration/Configurations.json`. For example, `[{ "File": "match.cfg", "Label": "Match settings" }]` adds `cfg/match.cfg`. The shipped list is empty; nothing runs automatically. The menu accepts up to 64 distinct filenames with single-line labels. Selecting a config rechecks permission, the current list, and file existence. `reloadadmins` reloads SourceJS authorization and redraws the server actions if the caller still has access.
- The administration menu uses radio menus when `ShowMenu` is available and ESC dialogs otherwise. The renderer applies to the root, map and server actions, and player actions, including ban durations and reasons, slap damage, and communication restrictions. If neither renderer can send the menu, use console commands. Changing menus, disconnecting, ending the map, or unloading the plugin invalidates old selections.
- `nextmap` reports a valid `nextlevel` override or the next valid map in the map cycle. Set `sjs_nextmap_enabled 1` for sequential rotation, `sjs_randomcycle 1` for random rotation, `sjs_mapchooser 1` for automatic votes, `sjs_nominations 1` for nominations, or `sjs_rockthevote 1` for player-triggered voting. These options default to off.
- `sjs_listmaps` prints the loaded rotation in order, one map per console line. Maps the engine no longer recognizes are omitted. In chat, `/listmaps` and `!listmaps` also tell the caller where to find the list. Use `sjs_mapchooser_refresh` with `sourcejs.map` to reload the cycle after editing it. During a rotation vote, including a runoff, refresh is rejected without changing the loaded list or the ballot. Other votes do not block a refresh. Refresh does not change an already selected `nextlevel`.
- Set `sjs_mapcyclefile` to use a custom `.txt` cycle, including on engines without `mapcyclefile`. SourceJS looks in the game directory first, then under `cfg/`. An empty `sjs_mapcyclefile` (the default) uses the engine's `mapcyclefile` value, or `mapcycle.txt` if it is unavailable. Run `sjs_mapchooser_refresh` to apply a new file without changing maps. An invalid path, unreadable file, or file without installed maps does not replace the previous cycle or clear nominations. At map activation the same failure is logged and the previous list stays available, if one was loaded.
- Set `sjs_mapcyclefile "*"` and run `sjs_mapchooser_refresh` to use the installed maps in the engine's `GAME` search path, sorted by name. With an empty override, SourceJS also tries this list if the default cycle cannot be read and there is no usable previous list. An invalid explicitly configured file does not trigger the fallback.
- Sequential rotation wraps from the last map to the first. On a normal map start, random rotation checks `sjs_randomcycle` and rereads the map cycle five seconds after activation so startup configs can take effect. The random choice can replace the sequential choice made by the plugin at activation, but not an existing valid override for a different map, a manual selection, or an active or completed rotation vote. It excludes the current map and the last `sjs_randomcycle_exclude` maps (default: `5`), relaxing the oldest exclusions first if needed. Refreshing the cycle manually cancels a pending random choice and leaves `nextlevel` unchanged.
- When the server visits a map outside the cycle, sequential rotation resumes after the last cycle map observed by the plugin, unless there is a valid `nextlevel` override. It uses the current cycle order. If there is no remembered map, or that map is no longer in the cycle, it starts at the first valid entry. This position is not retained across plugin reloads.
- Sequential rotation replaces a failed `nextlevel` with the next valid, untried map in the cycle. This runs when an engine reports `server_changelevel_failed`, or when a delayed SourceJS request finds the map missing or cannot submit the change. It does not issue another map change or override a different `nextlevel`. If no eligible map remains, it clears `nextlevel`. The failed-map list resets on map activation.
- `sjs_maphistory` requires `sourcejs.map`. It prints the current map and up to 20 previous sessions in the console, most recent first, with UTC start time, elapsed wall-clock time, and change reason. Chat invocation points the caller to the console. SourceJS records its own change reason when the requested map actually loads; other transitions show `Engine or unknown`. History starts when the plugin observes map activation and is not retained after plugin unload.
- The bundled `server-protection` plugin checks global and team chat for flooding before handling `!` and `/` commands. `sjs_flood_time` sets the minimum interval between chat messages (default: `0.75` seconds; `0` disables it). Three messages within the interval accumulate three strikes; the next rapid message is blocked. A blocked message extends the cooldown by three seconds in addition to the configured interval. A message sent after the cooldown removes one strike. The warning goes only to the sender, with a console fallback if the game cannot display it in chat. Grant `sourcejs.flood` to bypass the filter. Reserved slots use `sjs_reserved_slots` (default: `0`) and the `sourcejs.reservation` permission.
- `/cookies` lists the exposed preferences. `/cookies AdminSounds` reads your own setting; `/cookies AdminSounds on` or `off` writes it. `/settings` opens a radio or ESC menu, with `/settings on|off` as a menu-free alternative. The older `/cookies on|off` shorthand still works. Reading or writing a value requires an authenticated Steam player. Saves are asynchronous, survive reconnects, and apply to `sjs_play` when the cache is loaded. A disconnect or map change closes pending settings menus.
- `sjs_play <target> <sound file or event>` requires `sourcejs.admin`, respects target immunity, and skips bots and players who disabled `AdminSounds`. It sends installed `.wav` or `.mp3` files as reliable, non-positional sounds, and submits sound events such as `UI.ButtonClick` with `playgamesound`. The `sound/` prefix is optional, and paths with spaces must be quoted. Event names may use letters, digits, underscores, hyphens and separating dots. Both paths recheck the recipient and submit separately; a rejection for one client does not stop the others. The caller gets the accepted submission count. After an accepted request, `sjs_show_activity` controls who sees the activity notice, which includes the count but not the sample name or target names. Acceptance does not confirm that the client heard the sound.
- `sjs_slap` and `sjs_slay` target live players and require `sourcejs.slay`. Group actions continue past individual failures and report how many targets were affected. Activity messages follow `sjs_show_activity`. Slay reports an accepted native request, not a death already visible through the player API. Slap defaults to zero damage; the admin menu offers `0`, `1`, `5`, `10`, `20`, `50`, and `99` before target selection. Slap adds an impulse to current velocity through [SDKTools GameData](api/players-entity.md#commands-events-and-moderation); if this is unavailable, the target is not damaged. Nonlethal damage is checked by reading back the target's health. A lethal slap preserves the target's frag count when GameData identifies a compatible field. This also applies to lethal hits on secondary targets of a timebomb, not to ordinary `sjs_slay` or the bomb carrier's death. Slap plays an installed impact sound when the selected SDK or game supplies one in GameData.
- `sjs_rename <target> [new name]` requires `sourcejs.slay`, accepts dead players, and randomizes the existing name if no replacement is supplied. A supplied name gets a numeric suffix for group targets. The menu rechecks access and target eligibility on selection. An unchanged name does not trigger another update or activity announcement. The server uses SDKTools `SetClientName` GameData and counts changes only after confirming the new name on the same connection. Confirmed changes are announced according to `sjs_show_activity`.
- `sjs_gag` blocks text chat, `sjs_mute` blocks voice, and `sjs_silence` does both; their `un` counterparts restore the corresponding channels. These commands require `sourcejs.chat` and target connected humans. The admin menu's **Gag/Mute player** action lists the operations that apply to the selected player's current state. Restrictions are per connection and cleared on disconnect. SourceJS reapplies existing voice mutes when a new listener becomes active and when a map activates, checking the current sender and listener UserIDs. A voice error for one listener does not stop reapplication for the others.

## Information triggers

Type `currentmap`, `nextmap`, `timeleft`, `thetime`, `ff`, or `motd` in chat without a prefix. Only a complete trigger matches, case-insensitively; the message remains visible. Replies go to the caller by default. Set `sjs_trigger_show 1` to share bare-trigger replies with all connected humans; this does not make `/` replies public or open the MOTD for other players. The `sjs_` console commands are also available.

`timeleft` reports the estimated time from map activation, along with supported round, win, and frag limits. Completed rounds without a winner reduce the displayed round allowance but do not advance MapChooser. The display counter resets at map start and on supported match-restart events. `sjs_timeleft_interval` announces it periodically in game time to player chat and the server console. Values below one second disable announcements (default: `0`; maximum: `1800`). Changing the setting starts a fresh interval, and a pending announcement does not carry into the next map. `nextmap` distinguishes an unresolved automatic map vote from a confirmed next map. `ff` reads `mp_friendlyfire` or, when absent, reports the survivor damage multiplier for games that expose difficulty-based friendly-fire settings.

`thetime` uses the server's local time zone. Set `sjs_time_adjustment` to a signed offset in seconds (default: `0`). `sjs_datetime_format` defaults to `%m/%d/%Y - %H:%M:%S` and supports `%Y`, `%m`, `%d`, `%H`, `%I`, `%M`, `%S`, `%p`, `%F` (ISO date), `%T` (24-hour time), and `%%` (literal percent). Use a single line; an empty format restores the default, and unsupported tokens produce an error.

## MapChooser

Enable `sjs_mapchooser 1` for automatic end-of-map votes. The plugin checks `mp_timelimit` every five seconds and opens the vote with `sjs_mapvote_start` minutes remaining (default: `3`). It also checks `mp_maxrounds` and `mp_winlimit` on completed-round events with `sjs_mapvote_startround` rounds or wins remaining (default: `2`), and checks `mp_fraglimit` against the attacker's live score on `player_death` with `sjs_mapvote_startfrags` frags remaining (default: `5`). A missing or zero limit does not trigger a vote. If another vote is open, a map change is pending, or there are no eligible voters, it waits and rechecks current limits. After enabling it mid-map, run `sjs_mapchooser_refresh` to start the periodic checks. Round tracking starts at map activation; TF2 uses its win-panel scores where available. Games without the relevant event do not get that event-driven trigger.

`sjs_mapvote` requires both `sourcejs.vote` and `sourcejs.map` for player callers. If an unrelated vote is open, the command queues one request and retries every five seconds, even if automatic voting is disabled. A queued request is dropped if the initiator disconnects, loses access, or the slot is reused. Map shutdown, plugin unload, a manual next-map selection, or an already scheduled map change also prevent the queued ballot from starting. A rotation vote already in progress does not queue another one.

- `sjs_mapvote_include` (default: `5`) caps the map choices. Nominations go first; the remaining choices are drawn at random from the cycle without repeats, excluding the current map and avoiding the last `sjs_mapvote_exclude` maps (default: `5`). On short cycles, recently played maps can fill the ballot to reach two choices.
- `sjs_mapvote_persistentmaps 1` keeps recent-map exclusions across a plugin reload or server restart (default: `0`). At map end the plugin writes up to 20 distinct names to `addons/sourcejs/data/plugins/server-administration/RecentMaps.txt` and restores them when first needed. MapChooser, nominations, and random rotation use the same list with their own exclusion limits. This does not persist the timestamps or reasons shown by `sjs_maphistory`.
- `sjs_mapvote_voteduration` sets the time per ballot (default: `20` seconds). With `sjs_mapvote_runoff 1`, the top two choices go to a second ballot if the leader falls short of `sjs_mapvote_runoffpercent` (default: `50`). Tied options are ranked in ballot order; if no runoff is needed, or if the runoff ends in a tie, the first tied leader wins. Options with no votes cannot win a tie.
- With `sjs_mapvote_novote 1` (default), an expired ballot with no votes selects a valid candidate as the next map, without forcing an immediate change. Cancelling the ballot explicitly does not select a map.
- If an automatic ballot ends without choosing a map, including when an administrator cancels it, periodic checks resume. The same limit and score that opened the previous ballot do not open it again; a new qualifying round or score, or a changed limit or threshold, can trigger another ballot.
- Set `sjs_mapvote_extend` to the number of extensions allowed per map (default: `0`). An extension increases only positive limits supported by the game: `mp_timelimit` by `sjs_extendmap_timestep` minutes (default: `15`), `mp_winlimit` and `mp_maxrounds` by `sjs_extendmap_roundstep` (default: `5`), and `mp_fraglimit` by `sjs_extendmap_fragstep` (default: `10`). A successful extension leaves `nextlevel` unchanged and restarts automatic checks. For SDKs where `mp_timelimit` is in seconds, set `sjs_mapvote_timelimit_seconds 1` for both scheduling and extensions.
- `sjs_mapvote_dontchange 1` (default) adds **Don't Change** to early votes instead of **Extend Map**. If it wins, no immediate or round-end change is scheduled. Either special choice can reach a runoff, but neither is selected by the no-vote fallback. The special choice takes one of the eight menu slots.

## Map nominations

Set `sjs_nominations 1`. Type `nominate` or `/nominate` to open the map list, or `/nominate <name>` to search the rotation. An exact match takes precedence over a partial match; several matches open a filtered menu. The current map and already nominated maps are visible but cannot be selected. By default the previous five maps are also unavailable; configure this with `sjs_nominate_excludeold` and `sjs_nominate_history`. Set `sjs_nominate_maxfound` to limit the partial-search menu (`0` means no limit).

New nominations are accepted up to the end-of-map ballot's map limit (`sjs_mapvote_include`, with one slot reserved if an extension would take the eighth slot). A player can replace their own nomination without losing its position even when the list is full. Administrators with `sourcejs.map` can use `sjs_nominate_addmap <map>` to force a map from the rotation into the next vote; this evicts the oldest nominations if necessary. The vote takes nominations first, then fills the remaining choices from the cycle. Nominations are consumed when the vote opens; they are also removed when their owner disconnects, the map leaves the cycle, or the level ends.

## Rock the Vote

When `server-administration` loads during a running map, it reads the cycle on the first simulating frame without changing a valid `nextlevel`. The RTV initial delay starts at that frame. Until the next map activates, SourceJS reports the configured round limit instead of rounds remaining, cannot estimate map time remaining, and does not start an automatic vote based on elapsed time. Round and win counters only include events observed since loading unless the engine supplies a score in the event.

Enable `sjs_rockthevote 1`, then use `rtv`, `rockthevote`, `/rtv`, `!rtv`, or the client console command `sjs_rtv`. Each connected human can request the vote once. Bots do not count. If a player leaves, the required number is recalculated.

- `sjs_rtv_needed` (default: `0.60`) sets the fraction of connected humans required, rounded up. `sjs_rtv_minplayers` (default: `0`) sets the minimum population.
- `sjs_rtv_initialdelay` (default: `30` seconds) opens RTV after map activation. `sjs_rtv_interval` (default: `240` seconds) controls when another attempt can start after reaching the threshold. RTV cannot interrupt an active vote or a scheduled map change.
- `sjs_rtv_changetime` chooses when to change to the winning map: `0` schedules the usual three-second map change, `1` sets the next map and schedules the change on a supported round-end event, and `2` leaves the change to the game at map end. If the game has no supported round-end event, mode `1` still sets the next map.
- Once a rotation vote or `sjs_setnextmap` picks the next map, `sjs_rtv_postvoteaction 0` (default) lets players request an early change to that map without another ballot. `1` closes RTV for that result. Writing a different `nextlevel` directly invalidates the recorded choice.

## Reserved slots

Set `sjs_reserved_slots` to the number of slots to reserve (default: `0`, off). The public limit is the game's maximum number of human clients minus the reserved count, with a minimum of zero. Bots do not count toward the public limit. Grant `sourcejs.reservation` to use reserved slots.

- `sjs_reserve_type 0` (default) denies new public clients above the public limit and lets reservation holders use remaining space.
- `sjs_reserve_type 1` also makes room when a reservation holder joins above the public limit. It selects an existing public client to disconnect.
- `sjs_reserve_type 2` acts like mode `1` until the number of connected reservation holders, including the joining player, reaches `sjs_reserve_maxadmins` (default: `1`). At that threshold, ordinary players can use the remaining slots.
- For displacement, eligible spectators take priority. `sjs_reserve_kicktype` chooses highest outgoing average latency (`0`, default), longest connection (`1`), or random (`2`). Bots and players with `sourcejs.reservation` or `sourcejs.reskick_immunity` are not displacement candidates. Kick immunity alone does not grant a reserved slot.
- `sjs_hide_slots 1` hides unused reserved slots where `sv_visiblemaxplayers` exists. The reported capacity does not drop below the number of connected humans unless the game already reports a lower maximum. Turning hiding off or unloading restores the preceding capacity override.

The plugin checks admission shortly after a client becomes active; it does not increase the engine's connection limit. When the engine is already full, a reservation holder still needs a free connection slot.

## Optional SQL administrators

Set `sjs_sql_admin_enabled 1` and run `sjs_sql_reload` from the server console. The plugin then loads the SourceJS `permissions.sqlite3` database asynchronously and refreshes its authorization cache on map activation. With SQL enabled, `sjs_reloadadmins` (including its administration-menu action) reloads the file configuration and requests an asynchronous SQL refresh, reporting the two results separately. SQL permissions supplement existing native permissions for these bundled admin commands; they do not replace flat-file permissions or grant rights to unrelated plugins.

From the server console, `sjs_create_adm_tables` ensures the SourceJS tables exist, and `sjs_update_adm_tables` adds a SQLite index for looking up group memberships. Both commands can be run again without changing existing permissions or group assignments. They work only on the SourceJS SQLite database and do not import external tables. Wait for the console reply before submitting another SQL command. If an empty dedicated server hibernates, the reply can be delayed until it resumes ticking.

```text
sjs_sql_addgroup Moderators sourcejs.kick
sjs_sql_addadmin STEAM_1:0:12345 Moderators
sjs_sql_setadmingroups STEAM_1:0:12345 Moderators
sjs_sql_deladmin STEAM_1:0:12345
sjs_sql_delgroup Moderators
```

Groups use SourceJS permission names. `sql_setadmingroups` replaces the SQL group list; omit groups to clear it. Deleting a group removes its SQL memberships and grants. Set the option back to `0` to stop using SQL permissions without deleting the database.

The demonstrations under `addons/sourcejs/plugins/disabled` do not load automatically. To try one, move its individual directory into `addons/sourcejs/plugins` and load it explicitly.
