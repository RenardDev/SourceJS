# `require("core/command/docs")`

> This page is maintained by hand. The generated file is a snapshot of registered runtime-module objects, not this API reference.

Requiring the module registers `sjs docs generate [strFileName]` on `CORE_COMMAND`. Calling
`GenerateModuleDocumentation()` directly writes a text snapshot of every currently registered native module and its sorted
own enumerable string-keyed export names. Symbol keys and non-enumerable exports are not included.

## Location and purpose

The implementation lives in [`packages/sourcejs/core/command/docs.js`](../../packages/sourcejs/core/command/docs.js). It resolves
the native `core` module through `internal/runtime`, reads the module names from `core.GetModules()`, resolves each listed module,
and writes a compact diagnostic index through `core/dumps`. Use it when an operator or plugin author needs a point-in-time
inventory of registered module objects and their current exports rather than hand-authored reference documentation.

## Import

```js
const { GenerateModuleDocumentation } = require("core/command/docs");
```

## Exports

| Export | Kind | Signature |
| --- | --- | --- |
| [`MODULE_NAME`](#module_name) | Constant | JavaScript module name, `"core/command/docs"`. |
| [`GenerateModuleDocumentation`](#generatemoduledocumentation) | Function | `GenerateModuleDocumentation(strFileName = "sourcejs-runtime-modules")` |

## Examples

### `GenerateModuleDocumentation`

The generated text starts with a comment identifying `core/command/docs.GenerateModuleDocumentation` as its generator and instructing readers to regenerate the snapshot instead of editing it. The function sorts the names returned by `core.GetModules()`. For each native module, it sorts the module's own enumerable
export names and emits a `## <module-name>` section followed by one comma-separated line. It writes the finished text through
`core/dumps.WriteDump()`, logs the returned path through `CORE_COMMAND`, and returns that path.

```js
const { GenerateModuleDocumentation } = require("core/command/docs");
const { ReadTextFile } = require("filesystem");

const g_strOutputPath = GenerateModuleDocumentation("diagnostics/runtime-modules");
const g_strDocumentationText = ReadTextFile(g_strOutputPath);
if ((typeof g_strDocumentationText !== "string") || !g_strDocumentationText.startsWith("<!-- Generated by core/command/docs.GenerateModuleDocumentation;")) {
	throw new Error(`Unexpected module documentation in ${g_strOutputPath}.`);
}

console.log(`Native module snapshot written to ${g_strOutputPath}.`);
```

The same operation is available through the shared command tree after this module has been required:

```js
const { CORE_COMMAND } = require("core/command");
const { MODULE_NAME } = require("core/command/docs");

const g_bCommandHandled = CORE_COMMAND.RunCommand("sjs docs generate diagnostics/runtime-modules");
if (!g_bCommandHandled) {
	throw new Error(`Unable to run the documentation command registered by ${MODULE_NAME}.`);
}

console.log(`Documentation command handled: ${g_bCommandHandled}`);
```

### `MODULE_NAME`

```js
const { MODULE_NAME } = require("core/command/docs");

console.log(`Documentation command module: ${MODULE_NAME}`);
```

## Safe use

- Treat `strFileName` as a trusted output path. Relative names are resolved under the SourceJS dump root, `.txt` is appended
  when absent, and absolute paths are accepted by `core/dumps`.
- Path resolution does not establish containment within the dump root. Reject embedded NUL in output names before calling:
  native file helpers reject embedded NUL with `TypeError` instead of targeting a shortened prefix.
- Use the returned path as the authoritative output location. Nested output directories are created when possible; an invalid
  name, unavailable dump root, directory-creation failure, or write failure throws.
- Requiring this module registers a command on the shared core command tree. Account for that side effect when loading command
  modules.
- The generated file covers only names returned by native `core.GetModules()`; it does not enumerate
  `core.GetPublicPackages()`.
- Each export list comes from `Object.keys()`, so inherited, symbol-keyed, and non-enumerable properties are omitted. JavaScript
  packages can augment a registered runtime object; those enumerable additions are included too. Regenerate after registration or
  package-loading changes, and do not treat the snapshot as a substitute for semantic API documentation.
- `RunCommand()` reports whether a matching callback completed, not the generated path; it discards the callback's return value.
  Generation exceptions propagate. A logging exception can occur after the file has already been written.
- The command callback uses the default filename when its first argument is absent or empty. A direct call defaults only when
  the argument is omitted or `undefined`; an empty string reaches `WriteDump()` and is rejected.
